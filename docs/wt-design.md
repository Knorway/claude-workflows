# wt 설계 — 무엇이고, 무엇이 아닌가

이 문서는 `wt`가 다음 프로젝트로 옮겨갈 때 재론하지 않기 위한 기록이다. 사용법은
[`plugins/wt/README.md`](../plugins/wt/README.md), 리뷰 루프의 근거는
[`review-loop.md`](review-loop.md).

## 1. 정체성

**한 사람이 한 머신에서 탭 여러 개를 돌리기 위한 반자동화 발판.**

팀 도구가 아니고 CI 제품도 아니다. 노리는 지점은 사람이 완전히 손을 떼기 어려운
프로젝트다 — UI/UX가 결과물의 핵심이거나, 시뮬레이터·기기별 엣지케이스가 많거나,
막 시작해서 판단이 계속 필요한 프로젝트. 기계가 볼 수 있는 데까지 밀어주고, **볼 수
없는 지점을 사람에게 정확히 넘기는 것**이 목표다. 전자동이 목표였던 적이 없다.

**한국어는 사고가 아니라 결정이다.** 사용자가 한 명이고 그 사람이 한국어를 쓴다.
i18n은 비목표다(§8). 이걸 "범용적이지 않다"의 근거로 다시 쓰지 말 것.

## 2. 불변식 셋

이 셋을 깨는 변경은 되돌린다.

1. **설정 0으로 동작한다.** `.claude/wt.json`은 플러그인이 배포하지도 생성하지도 않는
   선택적 파일이다. 없으면 모든 조회가 빈 문자열로 떨어지고 각자의 기본값을 쓴다
   (`wt-common.sh`의 `wt_cfg`/`wt_cfg_list`). 설정 파일 부재가 에러가 되는 코드 경로는
   없어야 한다.
2. **플러그인 스크립트는 레포가 준 문자열을 절대 `eval` 하지 않는다.** 단 하나의 예외가
   `provision.run`이고, 그래서 그것만 머신 단위 옵트인(`~/.claude/wt-run-allow`) 뒤에
   있다. 이것이 `wt-verify run <id>`가 없는 이유다(§6). — **이 불변식이 사주는 것은
   딱 여기까지다. §5의 "무엇을 못 사는가"를 반드시 함께 읽을 것.**
3. **못 돌린 검증은 이름으로 보고된다.** 침묵은 커버리지로 오독된다. 부재가 아니라
   보이는 줄이어야 한다.

## 3. 네 표면

| 표면 | 성격 | 프로젝트를 아는가 |
| --- | --- | --- |
| hooks + scripts | 기계적. git·파일시스템·프로세스만 다룬다 | **모른다** |
| `.claude/wt.json` | 레포가 채우는 **유일한 결합면** | 전부 여기 |
| commands (`/wt:*`) | 모델이 읽고 실행하는 산문 | 규약만(예: `CLAUDE.md`를 읽으라) |
| agents | 문맥 없는 리뷰어/반증자 | 모른다 |

## 4. 결합은 어디에 사는가

이 플러그인이 특정 프로젝트에 묶여 보인다는 의심은 거의 항상 **`wt.json`의 내용을 보고
플러그인을 판단**한 것이다. `wt.json`은 그 레포의 파일이고, 거기 그 레포의 용어가 있는
게 맞다.

**합격 테스트:** Go CLI 레포가 같은 스키마로 `go vet` / `go test` /
`docker build`(`worktree: false`)를 적을 수 있는가? 적을 수 있고, 플러그인 코드는 한 줄도
바뀌지 않는다. 이게 통과하면 결합이 아니다.

**중복 금지 — `wt.json`은 색인, `CLAUDE.md`는 매뉴얼.** `verify`가 버는 값은 기계가 읽는
부분(`id`·`worktree`·`human`)뿐이다. 그게 점호와 사람 게이트를 굴린다. 산문은 이미
`CLAUDE.md`에 더 잘 적혀 있다 — 왜 그 포트여야 하는지, 에뮬레이터가 어떤 식으로 죽는지,
정리 순서. **`note`는 그 산문을 가리키기만 하고 다시 쓰지 않는다.** 두 군데 적히면
갈라지고, 갈라진 `wt.json`은 `CLAUDE.md`의 JSON 사본이 되어 그때야말로 결합처럼 보인다.

**알면서 남겨둔 것 하나:** 설정이 없을 때 `node_modules`가 있으면 CoW로 복제한다
(`wt-provision.sh`). JS 색채가 맞지만 `[ -d ]` 가드가 있어 Go/Rust/Python 레포에서는
조용히 아무 일도 안 한다. 지우면 무설정 경로만 나빠진다.

## 5. verify 계약

`.claude/wt.json`의 `verify`는 **순서 있는 평평한 목록**이다. 싼 것부터 비싼 것 순.
티어는 두지 않는다 — 순서가 이미 비용을 표현하고, 기계가 알아야 하는 건 "얼마나
비싼가"가 아니라 **"여기서 돌릴 수 있는가"와 "기계가 판정할 수 있는가"** 두 불리언뿐이다.

| 필드 | 기본 | 의미 |
| --- | --- | --- |
| `id` | (필수) | 원장·점호의 안정된 키 |
| `run` | — | 원문 그대로 출력되는 명령. 여러 단계이거나 문서에 있는 절차면 생략 |
| `when` | — | 언제 돌리는지. **의도적으로 산문** |
| `worktree` | `true` | `false` = 워크트리에서 물리적으로 불가 |
| `human` | `false` | 기계가 세팅은 해도 판정은 못 함 |
| `note` | — | 한 줄 주의, 또는 문서 포인터 |

**`when`이 산문인 이유:** 모델은 자기가 무엇을 고쳤는지 이미 안다. glob DSL을 만들면
모델보다 못한 판정기를 새로 유지해야 한다.

**3단 하강.** ① 계약이 있으면 그대로. ② 없으면 디스크만 보고 **추정**한다
(`package.json` scripts + 락파일로 러너 판별, `Cargo.toml`, `go.mod`, `pyproject.toml`,
`Makefile`) — 그리고 **붙여넣을 수 있는 `verify` 블록을 함께 출력**해 저작 경로를 준다.
③ 아무것도 못 찾으면 "직접 찾아 돌리고 못 돌린 건 이름을 대라"고 알려주고 끝낸다.
계약이 깨져 있으면(배열 아님, `id` 없음) 경고하고 ②로 떨어진다. **절대 죽지 않는다.**

**원장**은 `$(git rev-parse --git-dir)/wt/verify-<브랜치>.tsv`. git-dir 부분이 **탭**을
가르고(워크트리에선 `<main>/.git/worktrees/<name>/`로 풀린다), 브랜치 부분이 **작업**을
가른다. 커밋될 수 없고 워크트리를 지우면 함께 사라진다.

브랜치로 가르는 게 미관 문제가 아닌 이유: 체크아웃은 재사용된다. 한 항목을 끝내고 머지한
뒤 같은 디렉터리에서 다음 항목을 시작하는데, 원장이 하나면 이전 작업의 `review=ok`가 남아
`/wt:remote-push`가 **리뷰를 통째로 건너뛴다** — 게이트가 존재하는 이유와 정확히 반대
방향으로 실패한다. 같은 브랜치에서의 두 번째 푸시는 remote-push가 푸시 직후 `review`를
`skip`으로 내려 처리한다. `wt-verify checks`가 **계약의 모든 id**를 찍고 기록 없는 것을
`미실행`으로 채운다 — 불변식 3의 구현체다.

브랜치로 가르면 **브랜치가 바뀌는 순간**이 문제가 된다. `/wt:remote-push`가 하는 일이
정확히 그것이다 — `main` 위에서 작업하고 검증한 뒤 푸시 시점에 브랜치를 딴다. 그래서
`wt-verify adopt <이전-브랜치>`가 있다. 이전 브랜치의 원장을 현재 브랜치로 옮기되
**현재 원장이 비어 있을 때만** 옮긴다(비어 있지 않다면 그쪽이 현재의 진실이다).
없으면 조용한 no-op이라 무조건 불러도 된다. 이게 없으면 실제로 돌린 검증이 전부
`미실행`로 보고되고, `review=ok`는 옛 브랜치에 남아 **다음 푸시를 무료 통과**시킨다.

**공짜 정직함:** `worktree: false` 단계는 워크트리에서 모델의 협조 없이
`건너뜀(메인 체크아웃 전용)`으로 보고된다.

**원장은 검증 결과만 담는 곳이 아니다.** `/wt:review`도 끝나면 `review=…`를 남기고,
`/wt:remote-push`가 그걸 보고 리뷰 없이 나가는 PR을 막는다(막는다기보다 `--quick`을 한 번
강제하고 지적이 나오면 묻는다). 세션 기록 대신 원장을 신호로 쓰는 이유는 컨텍스트가
압축되면 "이번 세션에 리뷰했는가"를 알 수 없기 때문이다 — 확신이 없으면 리뷰하는 쪽으로
실패해야 하고, 원장은 그 판단을 압축에서 살아남게 한다.

### 이 설계가 **못** 사는 것 (원래 과장했던 부분)

초안은 "실행은 모델이 하니 Claude Code의 permission 프롬프트가 이미 올바른 게이트"라고
적었다. **그건 과장이었다.** 리뷰에서 반박됐고, 반박이 옳다:

- **넓은 allow 접두사가 있으면 프롬프트가 아예 안 뜬다.** 이 워크플로를 쓰는 레포는
  `Bash(curl *)`·`Bash(git *)` 같은 규칙을 자연스럽게 쌓게 되고, 그러면 `run` 문자열은
  승인 없이 실행된다. 실제로 openstreetv2가 그 상태다.
- **명령을 실제로 읽는 주체는 사람이 아니라 모델이다.**

그래서 실제 신뢰 경계는 더 좁고 더 시시하다:

1. 사다리는 **primary 체크아웃의 `wt.json`을 먼저** 읽는다 — 내가 내 체크아웃에 커밋한 파일.
2. 검증 단계가 할 일이 아닌 모양은 `plan`이 **표시**한다(`risk_of`) — 셸로 파이프,
   비-로컬 네트워크, 셸 치환, 홈·비밀 경로, 파괴적 명령, 인코딩 해독. 로컬 `curl` 같은
   정상 계약에는 침묵한다. **매번 울리는 경고는 아무도 안 읽기 때문이다.**

**둘 다 "이상한 계약을 알아채는" 장치이지 "내가 이미 커밋한 것을 통제하는 공격자를 막는"
장치가 아니다.** 표시는 휴리스틱이라 우회는 얼마든지 가능하다. 실행 대신 출력하기는 구멍
하나를 없앤 것이지, 그것만으로 이 기능이 안전해지지 않는다.

**계약은 primary 체크아웃의 것이 이긴다.** `wt.json`은 커밋되는 파일이라, 지금 서 있는
체크아웃은 남이 쓴 브랜치일 수 있다. 그런데 `/wt:review`는 그 브랜치를 고친 뒤 이 사다리를
읽어 무엇을 돌릴지 정한다 — 리뷰 대상이 리뷰 절차를 정의하는 순환이 닫힌다. primary는
**내가 그렇게 두기로 한 상태**이므로 primary가 먼저다. 현재 체크아웃은 primary에 계약이
아예 없을 때만 폴백으로 쓰이고, **그 경우 `plan`이 소리 내어 알린다** — 레포가 준 명령이
내 체크아웃 밖에서 온 유일한 경로이기 때문이다.

**구현 주의 두 가지.** 필드 구분자는 탭이 아니라 US(`0x1f`)다 — `IFS=$'\t' read`는 탭이
IFS 공백이라 연속 구분자를 접고 빈 필드를 삼킨다. 그리고 두 불리언은 jq `//`가 아니라
`has()`로 읽는다 — `//`는 `false`를 빈 값으로 취급해 `"worktree": false`를 `true`로
되돌린다.

## 6. 사람 게이트 — 무엇이 **아닌지**가 설계다

`"human": true` → `wt-verify note <id>=human:"볼 것"` → `wt-verify checks`가 PR 본문에
`- [ ] **사람 확인 필요** · …` 체크박스로 렌더. 끝이다. 게이트는 사람이 이미 있는 곳(PR)에
진짜 체크박스로 산다.

의도적으로 **하지 않은** 것들:

- **`/wt:check` 커맨드가 아니다.** 쳐야 기억나는 커맨드는 건너뛰어진다. 턴도 하나 더 든다.
- **TODO.md의 상태가 아니다.** 사람 게이트는 *변경 하나*의 성질이지 *항목*의 생애주기가
  아니다. 원장과 PR 본문에 두면 항목 상태를 안 건드리고도 표현된다.
- **`/wt:remote-push`를 막지 않는다.** 한 번 거부당하면 그 커맨드를 안 쓰게 된다. 보고가
  전부이고, 보고로 충분하다.
- **`wt-verify run <id>`이 아니다.** 사용자에게는 불투명한 id가 보이고 뒤에서 레포가 적어둔
  아무 명령이나 도는 구조 — 프롬프트 세탁이다. 불변식 2를 정면으로 깬다. (다만 이걸 안 만든
  것이 안전을 보장하지는 않는다 — §5의 "못 사는 것" 참고.)

## 6.5. TODO 항목의 생애주기와 "상태를 늘리지 마라"의 진짜 의미

```
- [] 본문                 자유, 선택 가능
- [-] 본문  #<slug>       점유, 이 탭이 작업 중
- [~] 본문  #<slug>       PR 올라감, 머지 대기
- [x] 본문                완료 (점유도 함께 끝남)
```

§6에서 "상태를 늘리지 마라"고 한 것은 **사람 게이트를 항목 상태로 만들지 마라**는
뜻이었다. `[~]`는 다른 종류다 — 항목 자체의 생애주기이고, `/wt:remote-push`가 PR을
올린 뒤 `wt-todo pr`로 찍는다. 점유는 유지되고 선택은 막히며, 사람이 머지 후 `[x]`로
바꾸면 기존과 똑같이 점유가 끝난다. PR이 닫히면 `release`가 `[]`로 되돌린다.

**진짜 규칙은 이것이다: 새 상태를 만들면 `list`/`claim`/`pr`/`release`/`mine`을 한꺼번에
가르쳐야 한다.** `list`가 모르는 마커를 찍으면 항목의 상태가 바뀌는 게 아니라 **목록에서
사라진다** — 어느 탭도 그 항목을 다시 볼 수 없다.

**실제로 물린 것 하나:** 소유자 슬러그는 체크아웃 디렉터리 이름인데 `owner()` 정규식이
좁아서 파싱이 실패했다. claim은 `#my.app`으로 쓰는데 읽는 쪽이 못 읽으니
`release`/`pr`/`mine`이 조용히 아무것도 못 찾고 항목이 영구히 잠긴다.

**고치는 쪽을 틀리기 쉽다.** 처음엔 읽는 쪽 문자 집합에 `.`을 더했는데, 디렉터리 이름은
공백·한글·`@`도 담을 수 있으니 같은 버그가 그대로 남았다. 올바른 방향은 **쓰는 쪽을
제약하는 것** — 슬러그 생성 시 `[A-Za-z0-9_.-]` 밖의 문자를 `-`로 바꾸고, 통째로 사라지는
이름(전부 한글 등)은 원본의 체크섬으로 대체해 유일성을 지킨다. 쓰는 쪽 ⊆ 읽는 쪽이면
이 버그 클래스가 닫힌다.

| `TODO.md`를 ignore하지 않는 레포에서 `git add -A`가 스크래치패드를 PR로 내보냈다 | `todo.sh`가 `check-ignore`로 **파일을 만들기 전에** 거부 |
| jq 없으면 `plan-nudge.sh`가 매 프롬프트 exit 127 | 가드 추가 + README에 jq를 하드 의존성으로 명시 |
| 프로젝트마다 `settings.json` 손편집 | `--scope user` 설치를 기본 안내로 |
| `wt.json` 없으면 `.env` 빠진 워크트리가 조용히 잘못 빌드 | 프로비저닝이 **복사하지 않고 이름을 댄다** |
| `wt.json` 스키마를 기억해야 함 | `wt-verify plan`이 붙여넣을 블록을 출력 |

새 기능을 붙일 때마다 이 표에 한 줄씩 추가하며 같은 질문을 다시 던질 것.

## 8. 비목표와 로드맵

**비목표.**

- **i18n.** §1 참고.
- **notion/trello 프로바이더.** 단일 머신·로컬 목록으로 충분하다. 여러 머신/사람 협업이나
  모바일 UI가 실제로 필요해질 때까지 미룬다.
- **무인 루프.** 사람 게이트가 존재 이유다. 검토 없는 자동 머지는 이 도구의 목적과 반대다.
- **CI 승격.** 리뷰 루프를 CI로 올리는 논의는 [`review-loop.md`](review-loop.md) 소관.

**로드맵 — 지금 비어 있는 자리.**

- **워크트리 수거 경로가 없다.** `/worktree-clear`가 불안정해서 제거된 뒤 대체가 없다.
  `wt-remove.sh`는 Claude Code의 WorktreeRemove 이벤트에만 반응하므로, 머지된 워크트리와
  브랜치가 계속 쌓인다. 다시 만든다면 실패 모드를 먼저 정할 것 — 이전 구현은 디렉터리가
  이미 사라진 뒤 `git worktree remove`가 실패하면서 브랜치 삭제를 건너뛰었다.
