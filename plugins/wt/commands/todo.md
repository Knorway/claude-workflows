# /wt:todo

멀티탭 워크플로우의 선택·점유·작업 커맨드. 워크플로우는 **탭마다
`claude --worktree <name>` 세션을 열고 그 안에서 `/wt:todo`** 를 치는 것. 모든 탭이
**메인 체크아웃 루트의 `TODO.md` 한 파일**을 보므로, 한 탭이 점유한 항목은 다른
탭에서 빠져 경합이 없다.

인자: `$ARGUMENTS`

**철칙: TODO.md를 직접 Read/Edit 하지 말 것.** 워크트리에서 `./TODO.md`는 그
워크트리 자기 사본이라, 거기 쓰면 메인에 반영 안 되고 다른 탭도 못 본다. 모든
읽기·쓰기는 `wt-todo` 로만 한다 — 이 명령은 플러그인이 PATH에 올려주고, 스스로
메인 체크아웃을 절대경로로 찾아 그 한 파일만 만진다.

## 0. 프로바이더 라우팅

`$ARGUMENTS`의 첫 토큰으로 분기:

- `notion` / `trello` → **미구현.** "로컬만 지원됨. `/wt:todo`(인자 없음)로 로컬
  사용"이라고 답하고 멈춘다. (나중에 프로바이더가 붙을 자리.)
- `auto` → 로컬 + auto 선택(§2).
- 그 외(인자 없음 포함) → 로컬 기본.

## 1. 선택 (단일 번호 목록)

`wt-todo list` 를 실행하고 **그 출력을 사용자에게 그대로 보여준다.** 형식:

```
  [1]  L1   서버 에러시 메시지.
  [2]  L11  컴포넌트화 하기. 재사용과 테스트 가능성
  ...
  ── 진행중(점유, 선택 불가) ──
  [-]  L1 ...  #other-slug
  ── PR 올라감(머지 대기, 선택 불가) ──
  [~]  L4 ...  #other-slug
  완료: 5개
  # MAP 1:1 2:11 3:13 ...
```

두 블록은 해당 상태의 줄이 있을 때만 나온다 — **없다고 형식에서 지우지 말고, 있는데
접지도 말 것.** 어느 항목이 머지 대기인지가 화면에서 사라지면 사용자는 그걸 다시
집으려 든다.

그리고 이렇게 묻는다: **"claim할 번호를 답장으로 보내줘 (예: `1 3 7`)."**
`[1..N]`은 선택 가능한 `[]` 항목이고, `[-]`(다른 탭 점유)·`[~]`(PR 올라감, 머지
대기)·`[x]`(완료)는 선택지에서 빠져 있다. `# MAP` 줄은 `순번:줄번호` 매핑이다 — 화면에 그대로 노출할 필요는 없다.

**AskUserQuestion을 쓰지 말 것** (옵션 4개 캡이라 목록이 쪼개진다). 그냥 텍스트
목록 + 답장.

## 2. auto 모드

`/wt:todo auto` 면 `list`를 읽고, **주제가 같거나 파일 범위가 독립적이라 이 탭에서
함께 처리해도 충돌이 없는** 항목들을 스스로 배치로 묶어 "이거 묶어서 할게: [n], [m]"
라고 제안하고 확인받는다. 확신이 없으면 하나만 제안한다.

## 3. 점유 (claim) — 줄번호로

사용자가 순번(예: `1 3 7`)을 답하면, **방금 본 `list` 출력의 `# MAP`(또는 `[n] Lnn`
표시)로 순번 → 줄번호를 매핑**한 뒤 그 줄번호들로 claim한다:

```bash
wt-todo claim 1 13 23        # ← 순번 1,3,7 이 각각 L1,L13,L23 였다면
```

**claim은 선택 답장을 받은 그 턴의 첫 번째 도구 호출이어야 한다 — 예외 없음.**
plan 모드 전환 제안, `EnterPlanMode`, 탐색용 Read/검색/Bash, 그 무엇도 claim보다
앞서면 안 된다. "plan 모드니까 탐색·플랜 먼저 하고 claim은 나중에"는 금지 — 그 사이
다른 탭이 같은 항목을 가져가는 경합이 실제로 발생했다. 플랜이 필요한 작업이면
**claim으로 `[-]`를 박은 직후 `EnterPlanMode`로 스스로 진입해** 탐색·설계를 이어간다
(사용자에게 모드를 바꿔달라고 요청하지 않는다). 플래닝은 하나도 잃지 않는다 — 순서만
claim이 먼저일 뿐이다.

세션이 **plan 모드로 시작된 상태**라면 claim(쓰기)이 막힌다. 그때는 탐색을 시작하지
말고 shift+tab으로 해제를 요청해 claim부터 처리한다 — plan 모드를 유지한 채 탐색부터
하는 것이 정확히 경합을 만드는 행동이다.

### 세션 권한 설정 (레포 주인이 정할 것 — 플러그인이 강제하지 않는다)

이 커맨드는 두 가지 마찰을 만날 수 있고, 둘 다 **선택 사항인** 설정으로 없앨 수 있다.
플러그인은 권한을 배포하지 않는다([설계상 불가](https://code.claude.com/docs/en/plugins-reference)).

1. **첫 claim의 permission 프롬프트.** 아무것도 안 해도 된다 — 최초 1회 프롬프트에서
   "Yes, don't ask again"을 고르면 규칙이 **레포 루트의 `.claude/settings.local.json`**에
   저장되어 메인 체크아웃과 **모든 워크트리**에 영구 적용된다(v2.1.211+). 그마저 없애려면
   같은 파일 allow에 `Bash(wt-todo *)` 한 줄.
2. **`defaultMode: "plan"` 레포.** 매 선택마다 위의 shift+tab 경로로 떨어진다. 이게
   거슬리면 `defaultMode`를 `default`로 내리되, **커밋되는 `.claude/settings.json`이 아니라
   `.claude/settings.local.json`에** 넣는다 — Local 스코프가 Project를 이기고(권한 `allow`만
   merge되고 `defaultMode`는 precedence), gitignore라 클론하는 사람·CI에 영향이 없으며,
   레포 루트로 해석되므로 모든 워크트리 세션이 그 값을 받는다.

   **이건 안전 게이트를 내리는 결정이다.** 그 레포 `allow` 목록이 넓다면(`Bash(git *)` 등)
   plan 모드가 막아주던 것들이 무승인 실행 경로가 된다. claim 하나 때문에 치를 값인지는
   레포 주인이 판단할 몫이다 — 1번만 해두고 plan 디폴트를 유지하는 선택도 완전히 유효하다.

claim은 각 줄이 아직 점유되지 않았을 때만 primary `TODO.md`의 그 줄을
`- [] 본문` → `- [-] 본문  #<slug>`(진행중, 소유자 표시)로 **락 아래에서 원자적으로
다시 써서** 마킹한다 — 그래서 `list`를 돌리지 않고 파일만 열어도 누가 무엇을 잡았는지
보인다. 이미 점유된 줄은 `skipped`로 알려준다(그 사이 다른 탭이 가져간 것).
`release`는 반대로 **내 slug가 붙은** `[-]` 줄만 `[]`로 되돌린다. **진실의 원천은
`TODO.md` 한 파일뿐이고, `[-] … #slug` 그 자체가 점유다** — 별도 원장이 없으니
어긋날 것도 없다. **stderr의 claimed/skipped 결과를 사용자에게 그대로 전한다.**
하나도 claim되지 않았으면(전부 skipped) 작업을 시작하지 말고 그 사실을 알린 뒤 다시
`list`를 보여준다.

- `TODO.md`는 **gitignore되어야 하는 머신 로컬 파일**이다 — git에 안 잡히므로
  `git status`에도 안 뜨고, 브랜치 checkout/전환/pull/merge가 내용을 건드리지
  않는다. 그 덕에 메인에서 무엇을 하든 목록·점유가 안 흔들리고, 실수로 `git add -A`를
  해도 remote로 샐 게 없다. (레포의 `.gitignore`에 `/TODO.md`와 `/TODO.md.lock`이
  없으면 먼저 추가할 것을 제안한다.)
- 슬러그는 스크립트가 이 탭의 체크아웃 디렉터리 이름에서 자동 부여한다(따로 넘기지
  않음).
- 점유 마커가 항목 줄 자체에 붙어 있으므로 줄이 밀리든 본문을 고치든 점유가 그대로
  따라간다. 사람이 `[-] … #slug` 줄을 `[x]`로 바꾸면 점유도 함께 사라진다(따로 풀
  필요 없음).

## 3.5. 메모 추가 (`add`)

작업 중 떠오른 개선점은 **어느 탭에서든** `wt-todo add "<메모>"`로 primary `TODO.md`에
`- [] <메모>` 한 줄로 쌓는다(스크립트가 lock 걸고 primary 한 파일에 append).
워크트리엔 로컬 `./TODO.md`가 없으니(gitignore) 손으로 편집하지 말고 항상 `add`를 쓸
것 — 그래야 다른 탭도 본다.

## 4. 작업 착수 (점유 직후, 같은 턴에서 — 필수)

**순서 철칙: 선택을 받으면 무엇보다 먼저 `claim`을 실행해 점유 마크(`[-]`)를 박은
다음에만 작업을 시작한다.** 플랜을 짜거나 파일을 열거나 다른 어떤 것도 claim보다
앞서면 안 된다 — claim을 건너뛰고 작업부터 하면 그 사이 다른 탭이 같은 항목을 가져가
경합이 난다. claim의 `[-]` 마킹이 `TODO.md`에 즉시 남으므로, 그게 찍혔는지 확인하는
것으로 "claim 먼저" 규칙을 스스로 검증한다.

**claim이 하나라도 성공했으면 여기서 턴을 끝내지 말고 즉시 그 항목들의 작업을
시작한다.** (`wt-todo mine` 으로 방금 점유한 항목을 다시 확인할 수 있다.)

1. 플랜 → 구현. 사소하지 않은 항목이면 claim 직후 `EnterPlanMode`로 진입해 탐색·설계하고,
   `ExitPlanMode`로 승인을 받은 뒤 구현한다.
2. 검증: **`wt-verify plan`** 을 돌려 이 레포의 검증 사다리를 받는다. 출력된 명령을
   **네가 직접 실행한다** — `wt-verify`는 출력만 하고 아무것도 실행하지 않는다. 각
   단계의 `언제:` 조건을 이번 변경에 비추어 판단해 해당하는 것만 돌린다. 그리고
   결과를 남긴다:

   ```bash
   wt-verify note typecheck=ok codegen=ok api=skip:서버미기동
   ```

   `[메인 체크아웃 전용]` 단계는 워크트리에서 돌리지 말 것(자동으로 건너뜀 처리된다).
   `[사람 확인]` 단계는 기계가 판정할 수 없으므로 **무엇을 봐야 하는지**를 적어 넘긴다:
   `wt-verify note sim=human:"마커 탭 시 시트가 60% 높이로 올라오는지"`.
   기록하지 않은 id는 `wt-verify checks`에서 `미실행`으로 드러나므로, **못 돌린 것을
   숨길 방법이 없다 — 숨기려 하지 말고 사유를 적어 `skip`으로 남겨라.**
   사다리 자체가 없는 레포면 `wt-verify plan`이 무엇을 하라고 알려준다.
3. PR: `/wt:remote-push` 재사용 — `## 확인`에 위 점호가 그대로 들어가고, PR이 올라가면
   이 탭이 점유한 줄이 `[-]` → `[~]`(PR 올라감, 머지 대기)로 바뀐다.
   **사람 확인이 걸린 항목이 있으면 그 작업을 "완료"라고 보고하지 않는다.** 기계가 볼
   수 있는 데까지 끝났을 뿐이고, 무엇을 사람이 봐야 하는지 함께 말한다.

작업을 중도 포기하면 점유를 풀어준다: `wt-todo release`(이 탭이 점유한 것 전부) 또는
`release <lineno...>`.

## 5. 범위 밖 (지금 안 함)

- 완료 표시(`[x]`)·머지: 지금 스코프는 "경합 없는 선택·점유·이 탭 작업·PR까지"다. 머지는
  항상 사람이. `TODO.md`는 머신 로컬 스크래치패드라 `[x]`·본문 편집·`add`·claim의
  `[-]`·PR의 `[~]` 마킹은 전부 **로컬 기록일 뿐 커밋하지 않는다**(git에 안 잡힘). 즉 완료
  표시는 그냥 로컬 목록 정리이고, 실제 산출물은 PR이다. 다만 `[-]`/`[~] … #slug` 줄을
  `[x]`로 바꾸는 순간 그 줄은 더 이상 점유 상태가 아니므로 **점유도 같이 끝난다** —
  머지 후 따로 `release`를 부를 필요가 없다.
- `notion`/`trello` 프로바이더 구현. (현재 조율은 단일 머신·로컬 목록으로 충분하므로
  외부 스토어는 여러 머신/사람 협업이나 모바일 UI가 실제로 필요해질 때까지 미룬다.)
